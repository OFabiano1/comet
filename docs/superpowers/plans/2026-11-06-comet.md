# Comet Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Desktop Electron app: paste a YouTube URL to download `.mp4` (up to 1080p) or `.mp3` (192 kbps), or paste a GIF URL (direct file or Tenor/Giphy page) to save the `.gif`.

**Architecture:** Plain Electron (no bundler). Main process (`main.js`) owns child processes (`vendor/yt-dlp.exe`, fetch via Node), config file, and IPC. Pure logic lives in small CommonJS modules under `lib/` so it is unit-testable with `node --test` without Electron. Renderer is plain HTML/CSS/JS talking only through a `preload.js` contextBridge API.

**Tech Stack:** Electron (CommonJS), Node `fetch`, `node:test`, `yt-dlp.exe` + `ffmpeg.exe` in `vendor/` (never committed).

**Spec:** `docs/superpowers/specs/2026-11-06-comet-design.md`

## Global Constraints

- Windows; dev path contains `#`. No bundler/Vite/TS. CommonJS.
- `vendor/` and `node_modules/` gitignored; no binaries committed.
- Never silently overwrite an existing file (numeric ` (1)` suffix for GIF saves; yt-dlp `--no-overwrites -o` template for media).
- One download at a time; a stop button kills the child process and removes partial `.part`.
- Closing the window terminates child processes (no orphans).
- UI copy in Brazilian Portuguese, informal, not childish; no fake percentages invented by the app — show only real parsed progress.
- Errors always reach the status line with clear text; "yt-dlp outdated" is the primary expected failure → message points to the update button.
- Default quality pins (verbatim): mp4 → `-f "bestvideo[height<=1080]+bestaudio/best[height<=1080]/best" --merge-output-format mp4`; mp3 → `-x --audio-format mp3 --audio-quality 192K`.

## Review Focus

1. Input is not a GIF (page without media, direct URL to non-image) → visible clear error, nothing saved. Test: `test/gif-extract.test.js` returns `null`; main reports "Não encontrei GIF nesse link."
2. Outdated yt-dlp (YouTube extractor breakage) → error mentions update. Test: `test/ytdlp-args.test.js` covers stderr relay; manual step in Task 8 checks the status text path.
3. Network drop mid-download → status error `.part` cleaned up. Test: Task 6 unit test asserts cancel/kill cleanup behavior (same cleanup path).
4. Video title with `< > : " / \ | ? * ` or unicode → safe filename saved, extension preserved. Test: `test/naming.test.js`.
5. Wrong app action for link type (user clicks GIF on a YouTube URL) → app classifies first and reports mismatch, never runs the wrong tool. Test: `test/linkclassify.test.js`.
